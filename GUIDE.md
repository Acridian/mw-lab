# Руководство по работе с сайтом MW-LAB

Это руководство для тех, кто не является программистом, но хочет вносить изменения на сайт [mw-lab.ru](https://mw-lab.ru). Вся работа происходит здесь, в репозитории на GitHub.

---

## Основные понятия

**Репозиторий** — это место, где хранится весь сайт (тексты, изображения, код). Вы сейчас находитесь в нём.

**Задача (Issue)** — это ваш запрос на изменение. Например: «добавить новый товар», «исправить опечатку», «обновить контактный телефон». Задача описывает, что нужно сделать.

**Пул-реквест (Pull Request, PR)** — это набор готовых изменений, предложенных для добавления на сайт. Когда задача выполнена, ассистент создаёт PR с изменениями. Вы проверяете результат и подтверждаете публикацию.

**Ветка `main`** — это основная версия сайта. То, что находится в `main`, автоматически публикуется на [mw-lab.ru](https://mw-lab.ru).

---

## Как создать задачу (Issue)

1. Перейдите на вкладку **Issues** в верхней части репозитория.
2. Нажмите зелёную кнопку **New Issue**.
3. Напишите заголовок — кратко, что нужно сделать. Например: *«Добавить усилитель MW-2000 на сайт»*.
4. В описании напишите все детали задачи. Чем подробнее, тем лучше:
   - Что именно нужно изменить или добавить?
   - Есть ли у вас готовый текст, фото, ссылки?
   - Где на сайте это должно появиться?
5. Нажмите **Submit new issue**.

Готово! Задача создана, и ассистент может приступить к работе.

---

## Как отправить задачу ассистенту (OpenCode Agent)

После создания задачи нужно дать команду ассистенту. Это делается прямо в комментарии.

### Что написать

Напишите **`/oc`** (или `/opencode`), а затем — что нужно сделать, **на русском языке**. Ассистент понимает русский.

### Примеры

```
/oc Привет! Добавь на сайт новый товар. Название: Усилитель MW-2000. Описание: Мощный усилитель для лабораторий. Фото приложил.
```

```
/oc Исправь опечатку на странице контактов: вместо "телефон" написано "телифон".
```

```
/oc Обнови номер телефона в шапке сайта на +7 (999) 123-45-67.
```

```
/oc Добавь новость про нашу конференцию. Текст приложил файлом.
```

### Важные правила

- Команда должна начинаться с `/oc` в начале строки или после пробела (` /oc`).
- Пишите команду **в комментарии к созданной задаче (Issue)**.
- Ассистент сам прочитает вашу задачу, изучит сайт и выполнит работу. По окончании он создаст новый комментарий с пояснением, что сделано, и автоматически откроет пул-реквест (PR).

## Что делать с пул-реквестом (Pull Request)

Когда ассистент завершит работу, в репозитории появится **пул-реквест (PR)**.

### Как проверить изменения (предпросмотр на staging)

Одновременно с созданием PR автоматически запускается проверка. Внизу страницы PR вы увидите раздел с галочками:

- ✅ **PR Checks** — все проверки прошли успешно. Сайт собран без ошибок, вёрстка не сломана, ссылки работают.

Если видите ❌ — значит, что-то пошло не так. Напишите в комментарии к PR `/oc Исправь ошибки сборки`, и ассистент исправит.

### Как подтвердить и опубликовать

1. Откройте PR — просмотрите список изменённых файлов, прочитайте комментарий ассистента.
2. Если вас всё устраивает, нажмите зелёную кнопку **Merge pull request**, затем **Confirm merge**.
3. Изменения попадут в ветку `main`, и сайт автоматически обновится в течение 2–5 минут.

### Если результат не устраивает

Напишите в комментарии к PR:

```
/oc Внеси правки: <что именно поправить>
```

Ассистент обновит PR с учётом ваших замечаний.

---

## Как проверить публикацию на основном сайте (production)

После слияния (merge) PR изменения автоматически публикуются на [mw-lab.ru](https://mw-lab.ru).

### Где следить за статусом публикации

1. Перейдите на вкладку **Actions** (в верхней части репозитория).
2. Найдите запуск с названием **Deploy to GitHub Pages** — это самый верхний в списке.
3. Если строка зелёная ✅ — сайт обновлён и изменения уже доступны.
4. Если жёлтая 🟡 — публикация ещё идёт. Обычно это занимает 2–5 минут.
5. Если красная ❌ — произошла ошибка. Напишите `/oc` в комментарии к задаче, чтобы ассистент разобрался.

Нажмите на запуск, чтобы увидеть подробности и точное время завершения.

## Краткая памятка

| Что делаю | Куда нажимать | Что писать |
|-----------|---------------|------------|
| Хочу что-то изменить | Issues → New Issue | Заголовок и описание задачи |
| Запускаю ассистента | Комментарий к задаче | `/oc <описание задачи>` |
| Проверяю результат | Pull Requests → открыть PR | Смотрю изменения и статус проверок |
| Публикую изменения | Кнопка **Merge pull request** в PR | — |
| Проверяю, что сайт обновился | Actions → Deploy to GitHub Pages | Жду зелёную ✅ |
| Нужны правки | Комментарий к PR | `/oc <что поправить>` |

---

Если что-то непонятно или пошло не так — просто создайте новую задачу (Issue) с описанием проблемы, и ассистент поможет.
